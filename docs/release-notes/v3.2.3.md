# v3.2.3 — multi-turn session reuse fix (parent chain maintenance)

> 2026-08-08 · follow-up on v3.2.2's session-cache work

## What was broken

Reusing the same cached session for a second message in a row in the same
mode (stream or non-stream) returned an empty upstream response, failed
once, and only self-healed on the retry with a fresh session.

Root cause: the cached `parent_message_id` was never updated per turn. It
stayed `0`, so the second request sent `parent_message_id=0` to the
upstream in a reused `chat_session_id`, which the upstream answered with
an empty body.

## The fix

DeepSeek's SSE stream announces the message ids on the `event: ready`
frame (`request_message_id` / `response_message_id`). v3.2.3 captures that
and threads it through the whole chain:

1. **adapter** — `chat()` / `chat_stream()` accept a new `ready_out`
   callback dict. On seeing `event: ready` they fill
   `ready_out["response_message_id"]` (non-stream additionally falls back
   to `v.response.message_id`); when an internal retry swaps in a fresh
   session, `ready_out["session_id"]` carries the session that actually
   answered.
2. **server** — `AcquiredAccount.record_message_id(mid, session_id)`
   writes both the real upstream message id and the actual session id back
   into `SESSION_CACHE`, so the next turn's request body carries a valid
   `parent_message_id` in the same `chat_session_id`.
3. **bug in create_session** — the miss path stored the entry in
   `SESSION_CACHE` but never kept the object reference, so `record_message_id`
   previously no-oped even when called; the cached `ChatSession` object is
   now kept live and updated in place.
4. **all four handlers wired** — OpenAI/Anthropic × stream/non-stream all
   capture `ready_out` and record the chain after a successful turn,
   including the tool-call branches (they record before `[DONE]`).

## Behavior after

- Second and later turns on a cached session thread correctly with the
  upstream; no more one-shot empty responses for multi-turn reuse.
- When the adapter has to retry with a fresh session (rate limit / empty
  response), the cache's `chat_session_id` is updated to the new session,
  keeping the cache consistent.

## Verified

- Full pytest suite green (25 adapter + session-cache cases touch the new
  signatures; signatures remain backward compatible).
- Live multi-turn conversation through opencode against
  `/v1/chat/completions` streams correctly on turn 2+ (previously empty
  on turn 2).
