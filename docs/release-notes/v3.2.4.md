# v3.2.4 — upstream concurrency cap + incremental prompts (anti-flood)

> 2026-08-11 · reliability fixes found while using the proxy from opencode

## Problem

Two account-mute contributors surfaced under real agent usage:

1. **Parallel fan-out** — coding agents (opencode, Claude Code) spawn many
   parallel sub-agents; each maps to a concurrent `/v1/chat/completions`
   call. Without a cap, the proxy fired an unbounded number of upstream
   requests (each also creating a fresh session + PoW solve on retries),
   flooding DeepSeek with automation-shaped traffic.
2. **History resend** — agents always ship the full conversation on every
   turn. On a reused session, resending the whole flattened history made
   the DeepSeek conversation embed every previous turn in each message
   (quadratic growth) — a strong bot-spam signature. Repeated hits on
   either axis got the account muted (`biz_code:5 "user is muted"`).

## Fixes

- **`DEEPSEEK_MAX_CONCURRENCY`** (default `2`): a module-level
  `threading.BoundedSemaphore` gates every upstream request. Acquired in
  `_acquire()` *before* `pool.acquire()` (queued requests don't hold
  accounts busy), released idempotently in `AcquiredAccount.release()` —
  all exit paths (5 `finally` sites + the 503 path) are covered. Excess
  requests wait, they don't fail. Health checks stay exempt.
- **Incremental (delta) prompts**: `ChatSession.sent_prompt` stores the
  exact full prompt text of the last sent turn. `AcquiredAccount.
  prepare_prompt()` compares the client's full history:
  * extends the previous prompt → only the new tail is sent upstream
    (parent chain keeps the context server-side)
  * exact replay of the previous turn → sent again (client retry)
  * divergent history → the cached session is invalidated and a fresh
    chain starts (no duplicate-history accumulation on key collisions)
- **Mute detection**: upstream account penalties reply HTTP 200 with a
  plain JSON body (`data.biz_code:5`, `biz_msg:"user is muted"`,
  `mute_until`) that isn't SSE — previously parsed as "empty response"
  and blindly retried. Now `UserMutedError` (subclass of
  `RateLimitError`) is raised from both stream and non-stream paths and
  surfaces as a clear 429 with the unmute time, skipping pointless
  backoff retries.
- **Retry parent cleanup**: retrying with a fresh session no longer
  re-sends the stale session's `parent_message_id` (an invalid parent in
  a brand-new session reproduces the empty response).
- **`SESSION_CACHE_TTL` default 600 → 1800** so long-lived coding
  sessions stay threaded across 10+ minute idle gaps.

## Verified

- Stdlib assertion checks for `delta_prompt` (tail / replay / divergent /
  guards) and the semaphore cap (peak concurrency ≤ 2, all waiters
  complete).
- Live: server runs with the new code; the account-mute path returns a
  descriptive 429 instead of empty responses; multi-turn sessions reply
  correctly on turn 2+.
