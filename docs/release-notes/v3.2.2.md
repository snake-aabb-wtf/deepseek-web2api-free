# v3.2.2 — rate-limit backoff, hif headers, session-cache fixes, test coverage

> 2026-08-03 · 7 commits since v3.2.1 · reliability + test hardening

v3.2.2 makes the proxy resilient to upstream rate limiting, sends the new
hif signature headers, fixes the "streamed-then-non-streamed empty
response" root cause, and adds real unit coverage for the adapter and the
account pool.

---

## Rate-limit self-adaptation

- **Backoff retry** — when the upstream returns `rate_limit_reached`,
  `chat()` / `chat_stream()` retry with a fresh session after a configurable
  delay (`DEEPSEEK_RATE_LIMIT_RETRY_DELAYS`, default `5,15` seconds) before
  surfacing HTTP 429
- **Jitter default 0.4** — `DEEPSEEK_JITTER_SECS` now defaults to `0.4`
  (was `0`) to break perfectly-timed request patterns that trip the limiter
- **Rate limits don't poison the pool** — `RateLimitError` and transient
  empty responses no longer mark the account as errored, which previously
  drained the pool to a cascade of 503s

## hif signature headers

- New `_HifProvider` fetches `x-hif-leim` / `x-hif-dliq` from
  `hif-leim/hif-dliq.deepseek.com/query`, caches them for the announced TTL
  (default 600s, thread-safe), and attaches them to chat/completion
  requests (create_session excluded, matching the browser)
- Fetch failures degrade silently — the main request never fails because
  of hif

## Session-cache fixes (empty-response root cause)

- **Mode-scoped cache keys** — sessions are cached under `stream:` /
  `nonstream:` keys (OpenAI + Anthropic). Reusing a session created by a
  streamed call from a non-streaming call made the upstream return an
  empty response; same-mode multi-turn still works
- **Invalidate on failure** — `RateLimitError` / `UpstreamEmptyError`
  invalidate the cached session so the next call starts fresh instead of
  failing forever
- **Fresh Session for non-stream** — non-streaming completions use a
  dedicated curl_cffi Session to isolate from any dirty pooled connection;
  a response with neither content nor reasoning is treated as empty and
  retried once

## Test coverage (was zero for adapter/pool)

- `tests/test_adapter.py` — 15 cases: hint/toast scanning, empty-response
  retry, rate-limit backoff, hif provider + header attachment
- `tests/test_account_pool.py` — 10 cases: env fallback loading/priority,
  acquire fallback, stats/get_all, read-only protection, persistence
- CI unit matrix includes both files; full suite: **82 tests**

## Known follow-up

- Multi-turn reuse of the same cached session used to fail once before
  self-healing because the cached `parent_message_id` was never updated.
  **Fixed in v3.2.3** — see `docs/release-notes/v3.2.3.md`.

## Verified

- 82 pytest unit tests green
- End-to-end: streaming + non-streaming + expert requests all return
  content; stream→non-stream same-message no longer empties; hif fetch
  confirmed against the live endpoints
