# v3.3.1 — anti-flood hardening + bilingual docs

> 2026-08-11 · reliability + documentation release

## Highlights

- **Merged PR #11 (anti-account-mute)** — the biggest functional change since v3.3.0:
  - **Upstream concurrency cap** (`DEEPSEEK_MAX_CONCURRENCY`, default `2`): a global semaphore gates simultaneous upstream DeepSeek calls across all accounts. Coding agents (opencode, Claude Code) spawn parallel sub-agents that previously flooded the upstream and triggered account mutes. Extra requests now queue instead of failing.
  - **Incremental (delta) prompts**: on a reused multi-turn session, only the new tail is sent upstream instead of re-sending the full flattened history every turn (which caused quadratic history growth — a strong bot-spam signature). Divergent histories invalidate the cached chain and start fresh.
  - **Account-mute detection**: upstream penalties that reply `200 + JSON` (`biz_code:5 "user is muted"`) are now parsed — `UserMutedError` raises a clear `429` with the unmute time instead of being treated as an empty response and blindly retried.
  - **Retry parent cleanup**: retries on a fresh session no longer carry a stale `parent_message_id`.
  - **`SESSION_CACHE_TTL` default raised** `600 → 1800` so long coding-agent sessions stay threaded across 10+ min idle gaps.
- **Documentation overhaul**:
  - Added **`README_en.md`** — a complete English translation alongside the Chinese README, with a language switcher link at the top of both.
  - Removed the version-changelog blocks that had accumulated at the top of the READMEs (changelogs belong in `docs/release-notes/`).
  - Added a **non-interactive / automation account-pool configuration** section to README (both languages) and a dedicated `§15.8` + full env quick-reference in `AGENTS.md`.
